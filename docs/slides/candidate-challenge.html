The ask

Both products

Same company. Two places the software runs.

Cloud

  • Design, simulation, configuration, and ordering.
  • Two-week release cadence.
  • Vention owns the runtime.
  • Rollback is possible.

Edge

  • Firmware and software on controllers that drive real motion.
  • Customer-owned machines, often disconnected, often months behind.
  • No rollback on a machine mid-shift.
  • A failure stops a line or creates a hazard. A patch is possible and costly.

How you measure

A small set of numbers. Thresholds after a baseline.

CloudContinuous-integration pass rate. Flake rate. Web vitals. Post-deploy smoke.

EdgeEtherCAT link-loss during soak. Memory growth. Update success and resume rate. Pass rate across firmware versions.

BothEscaped defects. A number becomes a gate only after the baseline exists.

The v3.5.3 memory-leak soak follows the October 2026 notes: MachineLogic print and file-write leaks, and the remote-view recording leak. That release also fixed certificate trust. It does not mention EtherCAT.

Keep the bar

Sort defects by blast radius.

Find early

Before merge: unit tests, contract tests, the configuration handoff, and the emulator.

On the release candidate: motion, leaks, and update recovery.

Top class

A stopped line or a safety hazard on the edge. That machine cannot roll back mid-shift.

Close

A named owner closes it. Delivery sees the open list at the go or no-go.

Detect, triage, resolve

Bonus · field bug

An MMAI controller intermittently loses EtherCAT.

Before release
  • EtherCAT stays on the motor and link side of the contract tests.
  • The release candidate runs fault injection on real controllers.
  • A soak holds the link under a long run. Noise, load, heat, and a cold boot are guesses at the cause.
  • On the drive models the soak includes a full motor chain. Robot models stop at the link.
After it escapes
  • The case becomes a lab gate, and the ticket points at that soak.
  • MachineMotion AI 3.x still in the field stays in the matrix.
  • Link health joins the dashboard once a controller can report it.
  • v3.5.3 did not claim this fix, so the soak stays its own gate.
The field bug is intermittent, so the lab test has to be a soak

Order of the run

  • Health: GET /api/health expects status ok.
  • Setup signs in once and saves the session.
  • API tests, then Chromium and WebKit. The UI projects reuse that session.
  • A disposable design is created and deleted on teardown.

The challenge check

  • One MachineMotion AI shows in the bill of materials and in configuration.
  • A second controller is still listed. Download configuration shows an alert on each row.
  • Deleting one clears the alert. Two controllers cannot both be set up to automate that machine.
  • GitHub Actions runs the suite on pull requests and on master, and writes Allure.
Locale defaults to en-CA. A manual run can choose fr-CA.

First 100 days

The process starts from the current state.

Talk to the teams

Developers, Delivery, and leadership. Pain, thin test areas, and what makes the pipeline hard.

Read the signals you have

CSAT and NPS if they exist. Application and browser telemetry if they exist. The go or no-go Delivery already uses.

Then set the gates

Baseline the numbers on each target. A threshold arrives after that baseline, on the dashboard the teams already open.
